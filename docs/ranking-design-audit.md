## ความต่างที่ยังขึ้นกับข้อมูลและระบบเดิม

- **ข้อมูลคนละชุด:** HTML มีคลังผลงานจำลองใน localStorage ส่วนโปรเจคใช้ข้อมูลของโปรเจคและข้อมูลสำรองเดิม จึงมีชื่อเรื่อง ผู้เขียน สีปก คะแนน จำนวนเรื่อง และลำดับต่างกัน ไม่คัดลอกข้อมูลจำลองจาก HTML ไปทับข้อมูลโปรเจค
- **สถิติรวม:** ค่าบนหน้านับจากรายการผลงานที่โหลด ไม่ใช่ analytics รวมทั้งแพลตฟอร์มจาก endpoint สถิติโดยเฉพาะ บทบาทครีเอเตอร์คำนวณจากประเภทและต้นฉบับของผลงานที่มี ผู้สร้างหนึ่งคนมีได้หลายบทบาท
- **ประเทศต้นฉบับ:** ตัวเลือกทำงานกับฟิลด์ `country` แต่ชุดข้อมูลที่ตรวจไม่มีประเทศครบทุกเรื่อง และตัวแปลงข้อมูล API เดิมยังตั้งต้นฉบับเป็นไทย การเลือกประเทศที่ไม่มีข้อมูลจึงแสดง empty state แทนการสุ่มประเทศให้ผลงาน
- **ครีเอเตอร์:** ชุดข้อมูลอันดับเดิมมี ID จำลอง ไม่ใช่ ID โปรไฟล์สาธารณะที่ API เปิดได้ ปุ่มโปรไฟล์และติดตามจึงปิดใช้งานเมื่อไม่มี ID จริง ไม่สร้าง URL จากชื่อหรือบันทึกสถานะติดตามจำลอง หากมี `creatorId` จริง ปุ่มเชื่อมไปหน้าโปรไฟล์และใช้ขั้นตอนติดตามของหน้าโปรไฟล์เดิม
- **วันที่สมัครครีเอเตอร์:** ชุดข้อมูลอันดับไม่มีวันที่สมัคร จึงไม่แสดงวันที่ที่แต่งขึ้น ใช้จำนวนผลงานที่ตรวจพบแทน
- **แบนเนอร์จาก CMS:** ต้นแบบรองรับแบนเนอร์ที่ตั้งค่าใน localStorage แต่ไฟล์ที่ตรวจไม่ได้ตั้งค่าดังกล่าว งานนี้เทียบกับแบนเนอร์เริ่มต้นที่แสดงจริง ไม่ได้เพิ่มระบบ CMS ใหม่
- **มือถือ:** HTML ต้นแบบล็อกความกว้างเดสก์ท็อปและทำให้เลื่อนแนวนอนบนมือถือ โปรเจคยังใช้ layout ที่ปรับตามจอ มีเมนูแบบ drawer และตารางซ้อนแนวตั้ง ทดสอบที่ 390px แล้วเนื้อหาไม่ล้นแนวนอน

## การตรวจสอบ

- TypeScript: `npx tsc --noEmit`
- ESLint เฉพาะไฟล์ TypeScript ที่แก้
- Production build: `npm run build`
- ตรวจ whitespace: `git diff --check`
- ตรวจ UI ผ่าน Chrome DevTools ที่ 1440px, 1280px และ 390px รวม geometry, ตัวกรองประเภท/ประเทศ, empty state, ตัวเลือกช่วงเวลา, keyboard preview, Escape, การแบ่งหน้า, และการส่งไปล็อกอินจากปุ่มโหวต/เพิ่มเข้าชั้น
- ตรวจสถานะปุ่มครีเอเตอร์กรณีไม่มี ID จริง ไม่ทดสอบการโหวต เพิ่มเข้าชั้น หรือติดตามด้วยบัญชีจริง และไม่เปลี่ยนข้อมูลผู้ใช้
