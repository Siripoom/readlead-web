## การตรวจสอบ

- Chrome DevTools ตรวจเดสก์ท็อป 1440 × 1000 และมือถือ 390 × 844
- ทั้ง 4 แบบไม่มี horizontal overflow ที่ 390px มีแถบสนับสนุน 3 ส่วน แฟนคลับ 10 คน และ header/footer อย่างละ 1 ชุด
- ตรวจเลือกช่วง 1–50 และสลับลำดับ พบตอนแรก/ตอนที่ 50 ตามลำดับที่เลือก
- ตรวจการสลับแท็บนิยาย/หนังสือเสียง แสดงปุ่มเล่นและระยะเวลาในโหมดเสียง
- ตรวจเริ่มฟัง เปิด/ย่อเครื่องเล่น และเมนูตั้งเวลาปิด 15/30/60 นาที
- ตรวจป๊อปอัปแฟนคลับบนมือถือ มี Top 3 แท็บประเภทและช่วงเวลา ขนาดอยู่ใน viewport
- TypeScript, ESLint เฉพาะไฟล์ที่เปลี่ยน และ production build ผ่าน

## ข้อจำกัดของข้อมูลและการตรวจ

ข้อมูลผลงาน รูปปก รีวิว และคะแนนใช้ของโปรเจค จึงต่างจากตัวอย่าง MEMORIZE ใน HTML ไม่ได้นำเนื้อหาตัวอย่างนั้นมาทับข้อมูลผลงาน

อันดับแฟนคลับและเครื่องเล่นเสียงยังใช้ข้อมูล/กลไกจำลองเดิมของโปรเจค การแสดงเวลาเดินในเครื่องเล่นไม่ได้ยืนยันว่ามีไฟล์เสียงจริง การเชื่อมบริการเสียงและ leaderboard จริงต้องใช้ข้อมูล API เพิ่มเติม

สภาพแวดล้อมนี้เชื่อม CMS และ auth upstream ไม่ได้ โดย `/api/auth/session` ตอบ 503 จึงยังไม่ได้ทดสอบธุรกรรมจริงหลังล็อกอิน เช่น โหวต หักเหรียญ และซื้อ การ build สำเร็จพร้อมข้อความเตือนการโหลด CMS ใช้ข้อมูลตัวอย่างตรวจหน้าจอแทน

## ตรวจซ้ำเฉพาะรีวิวและแฟนคลับ

รอบแรกยังมีรายละเอียดคลาดเคลื่อน จึงตรวจ DOM และ computed styles ของอ้างอิงซ้ำ และแก้เพิ่มเติมดังนี้

- เอาดาวข้างชื่อผู้รีวิวและไอคอนดินสอบนปุ่มเขียนรีวิวออก คืนเส้นคั่นใต้หัวข้อและเอาเส้นคั่นท้ายรีวิวสุดท้ายออก
- เปลี่ยนปุ่มตอบกลับเป็นลูกศรทึบสีเทา แยกตัวเลขปฏิกิริยาให้มีความกว้างคงที่ และปรับระยะลิงก์ประวัติรีวิว
- เปลี่ยนข้อความสปอยเป็น “เนื้อหาที่มีการสปอย แสดงเนื้อหา” โดยข้อความเปิดสปอยเป็นสีแดง
- เปลี่ยนเมนูเรียงรีวิวเป็น dropdown ที่มีตัวเลือกพื้นแดงอ่อน รองรับการใช้งานด้วยคีย์บอร์ดผ่าน Base UI
- เพิ่มการแสดงจำนวนบทที่อ่าน ประวัติรีวิว และภาพผู้ใช้เมื่อข้อมูลมีฟิลด์เหล่านี้ ไม่สร้างยอดอ่านหรือประวัติสมมติให้ข้อมูลเดิม
- ประวัติรีวิวแสดงเวอร์ชันล่าสุดและเวอร์ชันก่อนหน้าในป๊อปอัป 560px การแก้ไขรีวิวในข้อมูล local ใช้ composer ในหน้าและเก็บเวอร์ชันเดิมไว้
- เนื้อหารีวิวตัดพร้อมลิงก์อ่านเพิ่มเติมในพื้นที่ 3 บรรทัด และขยาย/ย่อได้
- ช่องเขียนรีวิวใช้คำถาม “แนะนำเรื่องนี้ไหม” และปุ่มข้อความล้วน พร้อมตัวนับ 2000 ตัวอักษร
- เปลี่ยน avatar สำรองของรีวิวเป็นสีตามต้นฉบับ แฟนคลับใช้วงกลมสีพาสเทลตามลำดับ และปรับขนาด/ระยะของแถวกับลิงก์ดูเพิ่มเติมเป็นสีเทา

ทดสอบด้วยข้อความและข้อมูลรีวิวชุดเดียวกับอ้างอิงใน isolated browser context ชื่อ `detail-review-qa` โดยไม่ทับ localStorage ของ browser context ปกติ ตรวจพบจำนวนบทที่อ่าน 3 รายการ ลิงก์ประวัติ 2 รายการ ประวัติแรกมี 3 เวอร์ชันรวมล่าสุด และคำตอบกลับ 2 รายการตาม fixture ทดสอบเรียงเก่าสุด เปิดสปอย และเปิด/ปิดประวัติผ่าน บนมือถือ 390px ไม่มี horizontal overflow

ข้อมูลตัวอย่างของโปรเจคปกติยังเป็นข้อมูลเดิม จำนวนรีวิว ความยาวข้อความ คะแนนและรายชื่อแฟนคลับจึงต่างจาก HTML อ้างอิง ส่วนแถวอันดับของผู้ใช้แสดงเฉพาะเมื่อเข้าสู่ระบบ
